# KERV 昇腾：以任务精度为优先的量化设计

日期：2026-10-26。状态：原始设计记录，后续实施状态见下文。

后续状态：[原型试验报告](ASCEND_ACCURACY_AWARE_QUANTIZATION_PILOT_20261026.md)已完成group32与激活校准混合group的70回合试验。
本文保留设计时的计划；完整GPTQ与动作级敏感性联合搜索尚未完成，实施范围和结果以试验报告为准。

## 1. 推荐机制

采用 **真实VLA数据校准 + 按投影选择BF16/INT8 + 敏感投影使用更小group + 离线误差重建**。
保留现有NPU W8A16前向接口；将改进集中在量化权重如何生成、哪些Linear应该量化。

当前方案是对零起始7～24层的54个MLP Linear统一做group128、对称absmax量化，未使用真实输入校准。
新方案将`gate_proj`、`up_proj`、`down_proj`分别评分，选择具体模块，而不把整个连续层区间当作不可拆分的单位。
现有7/10对7/10包含四个任务成败互换，不能据此认定精度没有损失。

首要目标是尽量保持BF16策略的任务质量，满足显存要求后再选择时延更低的候选。期望成功率绝对下降不超过2个百分点，
同时检查相对下降和TestOutline要求；这是设计目标，不是已验证承诺。显存暂按更保守的2GiB节省设计，同时报告十进制GB。
量化校准不直接解决已测出的INT8 kernel性能代价；低误差与加速必须分别验证。

## 2. 初始精度分配

| 部分 | 初始策略 | 原因或处理方式 |
|---|---|---|
| vision、视觉projector、embedding、action/lm head | BF16 | 初始保守保护输入与动作输出链路，后续不据此宣称这些模块已被证明最敏感 |
| attention、RMSNorm、KV、drafter | BF16 | 先减少同时改变的数值路径；drafter仍可能受到verifier隐藏状态变化的影响 |
| verifier前2层和后2层MLP | 暂保留BF16 | 初始搜索范围约束；敏感性结论仍需实测 |
| 其余28层的84个MLP投影 | 分别选择BF16或W8A16 | 不预设哪种投影一定最安全 |
| 被选为INT8的低敏感投影 | group128优先 | 较少scale存储；实际kernel代价纳入筛选 |
| 中敏感投影 | 校准后尝试group64/32 | 增加scale以换取较低局部误差，按预算选择 |
| 高敏感投影 | BF16 | 用其他较低敏感度投影补足显存，而不是硬压同一批模块 |

混合精度以**整个Linear**为单位。第一版不把单个Linear拆成INT8与BF16两条在线分支，以免增加matmul、gather与合并开销。

## 3. 校准数据

不能只用现有task0的157帧来选最终配置。建议先采集LIBERO Goal全部10个任务、每任务至少2条独立BF16轨迹，
包括成功和失败、抓取/释放/接触、运动与静止、早期与后期步骤。轨迹数量是起始采样预算，覆盖不足时应补采。

保留原始TensorFlow crop、相机输入、语言指令、action归一化、动作协议、阈值和Kalman逻辑。
采集真实prefill以及验证树输入分布，避免使用通用语言文本代替图像和机器人动作上下文。
对每模块采样输入激活、BF16输出和必要统计，逐层流式处理；不一次把全部激活常驻NPU。

在采样前登记三份互斥的**轨迹/官方初始状态清单**：

1. 校准集：求scale、裁剪参数及重建权重。
2. 开发集：选择投影与group，检查接受情况和调优质量。
3. 最终评估集：配置冻结后仅用于报告质量，不再据其结果调参。

同一轨迹的相邻帧不得随机拆到不同集合。此前用过的init0与相关任务结果属于开发资料，不能重新称为未见数据。
最终评估从未用于调优的官方初始状态中预先登记，按TestOutline组织至少300回合并保留所有失败。
如果要对“小于某一损失边界”给出统计结论，应检查配对差值的区间；300回合不自动保证足够置信度。

## 4. 离线校准与敏感性

### 4.1 第一阶段：快速筛选

每次仅替换一个候选投影，比较BF16、当前RTN group128、RTN group64/32、校准重建后的group128。
参考输入为实际激活X，而不是随机矩阵。局部指标：

`E(module) = sum(||X W^T - X W_hat^T||²) / sum(||X W^T||²)`

分别报告prefill与验证token的误差、P95/P99，而不是让数量多的视觉/prefill token掩盖动作相关位置。
局部误差用于缩小搜索范围，不作为任务质量的替代指标。最终候选需再用真实NPU kernel复算输出。

### 4.2 第二阶段：离线重建

优先复用FlagScale已有GPTQ式逐层校准流程，根据校准激活的二阶信息补偿权重量化误差。
当前本地入口：`third_party/FlagScale/flagscale/compress/adapter.py`，含`GPTQWrapper`、
`ignore`、逐块校准与重建输出误差比较；尚未验证它能直接接受当前OpenVLA/KERV输入签名。
需要添加图像、语言及验证树输入适配，并核对依赖版本和NPU/CPU兼容性，不能把现有入口视为已经跑通。

导出约束：

- 对称INT8、BF16 scale、group32/64/128，保持当前`npu_weight_quant_batchmatmul`可消费的权重格式。
- 用实际BF16 scale与实际round/clamp规则评分，避免离线FP32假量化结果与部署不一致。
- 使用静态连续分组并保持原输入通道顺序；不导出需要推理时额外`g_idx`或通道重排的格式。
- 逐层校准时纳入上游已量化输出，最终再测组合误差；不能假设单模块损失可简单相加。
- 离线处理后只保留选定精度的部署权重，CPU完成量化再上NPU，原checkpoint只读。

GPTQ的算法参考来自[原论文](https://arxiv.org/abs/2210.17323)与[官方代码](https://github.com/IST-DASLab/gptq)。
其官方实现包含静态分组选项。这里复用校准思路和可兼容导出格式，不移植其CUDA推理kernel。
激活感知scale搜索也可参考[AWQ](https://arxiv.org/abs/2306.00978)；若采用，必须验证缩放能够离线折叠进相关权重/归一化，
并保持所有分支的函数等价，否则新增在线缩放成本应计入时延，不能默认其免费。

## 5. 按预算选模块

每个候选投影的选择项为`BF16`、`INT8/g128`、`INT8/g64`、`INT8/g32`。
敏感性、实际节省字节和真实形状的kernel耗时都写入表格。

从低损失候选开始累积，达到显存预算后停止扩大量化范围；将高损失模块提升精度，并从候选池中补充较低损失模块。
组合配置必须完整回放复核，不能把局部评分相加当作最终精度证明。
优先选择满足质量条件的配置，再比较时延；若没有同时满足目标的组合，应记录不可满足，而不是修改指标口径。

### 预算边界

当前一个MLP投影均有45,088,768个权重。group128改group32，单投影scale增加2,113,536 bytes。

| 改动 | 存储变化或推算 |
|---|---:|
| 54个投影全部group32 | 比当前额外114,130,944 bytes，约108.84MiB |
| 用此前完整Goal10峰值作简单扣减 | 节省2.339GB → 约2.225GB，即2.072GiB |
| 16个敏感投影改group32，其余group128 | 额外33,816,576 bytes，约32.25MiB |
| 一个group128 INT8投影恢复BF16 | 增加44,384,256 bytes，约42.33MiB |

上述是权重/scale算术与峰值推算，**不是新配置峰值实测**；workspace与allocator可能改变。
全部group32距离2GiB只有约74MiB推算余量，因此更推荐少数敏感投影group32、其余校准group128，并在预算规划中留出工作区余量。
最终以单模型完整加载和运行的实测allocated峰值为准，不用双模型诊断峰值或reserved池代替。

## 6. KERV专用质量验证

单看tensor L2误差不足以预测机器人任务结果。至少验证以下三层：

| 层级 | 比较内容 | 用途 |
|---|---|---|
| 固定上下文/固定候选树 | BF16动作token作为参考，合法动作词表上的分布KL、argmax/margin变化、动作bin距离、夹爪翻转、posterior接受变化 | 隔离verifier数值误差；不是自由闭环结果 |
| 固定图像的自由KERV回放 | 各自产生历史与验证树，统计原始接受长度、零接受、验证轮数、token工作量、P95与均值时延 | 检查量化与drafter/Kalman交互；不能代替任务成功率 |
| 完整LIBERO配对闭环 | 相同任务、初始状态、seed；成功率差、BF16独有失败/成功、步数与夹爪行为 | 最终判断任务质量，禁止只报总数掩盖成败互换 |

夹爪和接触阶段单列检查，不能让连续动作维度的平均误差掩盖离散开合改变。
固定上下文测试需要冻结相应mask、position、history与KV上下文；不能只冻结图像便称为相同验证输入。
所有候选保持原阈值、树路径与动作协议，避免用放宽接受条件掩盖误差。

精度目标：成功率绝对下降≤2个百分点作为工程目标，同时满足已约定正式相对/绝对损失口径。
接受长度、轮数和时延作为保护指标，优先筛除明显恶化候选；最终边界在运行前登记，不能观察结果后再调整。
7/10对7/10和局部0.5%L2都不足以宣称达标。

## 7. 首轮候选与实现顺序

| 配置 | 目的 | 状态 |
|---|---|---|
| C0：原中间18层、RTN/group128 | 可复现参考 | 已有完整Goal10与同卡时延记录 |
| C1：相同54投影、RTN/group32 | 快速判断更细group的质量收益 | 现有loader可运行；未做该配置闭环评估 |
| C2：相同54投影、校准重建/group128 | 尽量不增加部署存储/操作，以改善误差 | 需要接通校准与导出 |
| C3：按投影选择BF16/INT8与group | 兼顾敏感性、显存和时延 | 需要逐模块policy支持与组合验证 |

建议优先完成C2，再用C3处理剩余敏感模块；C1作低成本对照。
现有局部group探针：gate的L2误差group128为0.511%、group32为0.443%；down为0.638%与0.541%。
这里只证明这两个局部输入上的误差改善，不能预测任务成功率或新的整体加速比。

最小工程改动清单：

1. 新增真实VLA校准采集器、按轨迹划分清单与输入哈希。
2. 接通FlagScale GPTQ流程与当前对称INT8/BF16 scale导出；先做单投影真实kernel一致性检查。
3. 将`apply_cpu_mlp_int8`从连续layer范围扩展为逐模块policy，每项记录group、校准方法与来源哈希。
4. 保存`qweight/scale`部署产物、敏感性表、字节预算与配置，加载时拒绝权重/输入身份不匹配。
5. 复用已完成的同卡交替计时和LIBERO recorder，完成开发集筛选后冻结最终评估配置。

本轮仅形成设计；没有声称以上新流程已经实现或完成新LIBERO试验。
