# KERV 昇腾显存优化分析报告

> 2026-10-26更新：项目已允许使用量化。中间18层MLP的INT8方案已在本机10任务试验中
> 实测节省2.339GB，BF16/INT8均7/10成功；逐任务结果不同，不能外推严格5%质量边界。
> 见[新的量化验证报告](ASCEND_INT8_MEMORY_VALIDATION_20261026.md)。下文保留此前全部BF16常驻条件下的分析。


**主题：如何实现节省 2 GB 显存，以及当前实现的可行边界**  
**日期：2026-10-19**  
**范围：当前昇腾节点、本地自测；不作为正式验收通过报告。**

## 一、结论

1. 当前运行时优化已取得速度收益，但没有取得显存节省。本轮 B1→B2 的 `allocated` 峰值增加 **145,418,240 bytes**，`reserved` 峰值增加 **2,915,041,280 bytes**。
2. 若以当前 B1 为比较对象，并要求全部 BF16 权重继续常驻同一 NPU，**单靠 KV、临时张量和 allocator 优化，不能预期省出 2 GB**。按本轮参数量估算，常驻权重约 15.55 GB，已经高于“B1 峰值减去 2 GB”后的 14.89 GB 目标。
3. 任务书要求的基线是 **Spec-VLA B0**。本轮 B0 尚未完成本后端适配及参考等价性核对；不能把 KERV native B1 改名为 B0，也不能据当前 B1/B2 结果断言正式指标永远无法达到。
4. 建议先补齐同条件 B0，再做按阶段的显存归因，优先减少冗余驻留与临时结果。权重卸载和量化分别涉及传输、速度及精度条件变化，应另设实验，不能直接记为当前 BF16 系统优化的收益。

本文区分已测数据、计算推导和待验证方案；本次编写报告没有新增模型实验。

## 三、显存实测

本文 GB = 1,000,000,000 bytes；GiB = 1,073,741,824 bytes。正式采用哪个单位、哪种峰值，仍需按 D06 事前确认。

| 指标 | B1 bytes | B2 bytes | B2−B1 bytes | 结果 |
|---|---:|---:|---:|---|
| allocated 全程峰值 | 16,886,204,928 | 17,031,623,168 | +145,418,240 | 增加约0.145 GB |
| reserved 全程峰值 | 17,720,934,400 | 20,635,975,680 | +2,915,041,280 | 增加约2.915 GB |

对应 allocated 为 **16.886 GB / 15.727 GiB** 和 **17.032 GB / 15.862 GiB**。

### 两种峰值的含义

- **allocated**：框架统计的已分配张量内存；本轮用其全程最大值作主要观察。
- **reserved**：allocator 向设备保留的内存池，包含可复用空间，不能全部视作活跃张量。
- **设备/进程占用**：还可能包含运行时上下文和库工作区，需单独采集、核对归属。

B2 的两个峰值相差约3.604 GB，但峰值可能不在同一时刻，**不能直接把差额当成可释放量**。降低缓存或碎片可能改善占卡量，但不自动降低活跃张量的峰值。调用 `empty_cache()` 也不能将已经发生的 allocated 峰值抹去。

原始记录：[B1 memory.jsonl](../../../outputs/acceptance/ascend_20261019T0730Z/runs/paired_B1/metrics/memory.jsonl)、[B2 memory.jsonl](../../../outputs/acceptance/ascend_20261019T0730Z/runs/paired_B2/metrics/memory.jsonl)。

## 四、当前 B1 基线下的容量约束

本轮参数驻留记录为 **7,777,174,976 个参数，设备均为 npu:0**。按全部参数 BF16、每参数2 bytes估算：

```text
权重字节估算 = 7,777,174,976 × 2
             = 15,554,349,952 bytes ≈ 15.554 GB

若以 B1 为基线：
目标峰值 = 16,886,204,928 − 2,000,000,000
         = 14,886,204,928 bytes ≈ 14.886 GB

权重估算 − 目标峰值 = 668,145,024 bytes ≈ 0.668 GB
```

因此，在上述驻留假设下，即使将所有非权重占用都消除，目标仍低于权重估算约0.668 GB。现实中 KV、激活和工作区不能全部消除，所以所需的权重驻留调整通常更多。

该推导是**容量下界分析**，不是已完成的逐存储显存账本。后续仍须按实际 dtype、唯一 storage、共享/别名和 buffers 核对，不能只用参数个数替代精确字节审计。当前加载完成阶段采样约15.605 GB，与权重已构成主要占用的判断一致。

证据：[参数驻留记录](../../../outputs/acceptance/ascend_20261019T0730Z/runs/paired_B1/metrics/placement.jsonl)。

正式指标应计算 `peak(B0) − peak(B2)`。上述14.886 GB目标仅用于解释当前 B1→B2 的约束，**不是已确认的正式 B0 目标值**。

## 五、优化路线及取舍

| 优先级 | 路线 | 要做的具体工作 | 预期与限制 |
|---|---|---|---|
| P0 | 补齐真实 B0 | 移植并核对 Spec-VLA；冻结相同模型、BF16、batch、输入、任务和统计边界 | 确定正式差额，不能预设 B0 一定比 B1 占用更高 |
| P1 | 建立显存账本 | 分别统计唯一参数 storage、buffers、KV、持久工作区与临时结果；按加载、prompt、verify、commit标记峰值 | 找到真实大项；当前尚未完成 |
| P2 | 减少结果驻留 | 核对只保留首末层 hidden states、及时结束旧 logits/outputs/KV 引用、复用临时缓冲 | 优先保持相同计算；收益待测，不承诺累计2 GB |
| P2 | KV 与工作区容量优化 | 依据真实 prompt/tree 长度配置容量，检查旧/新 KV 是否重叠驻留及缓冲是否重复 | 保留全部候选和算法行为，不删路径制造收益 |
| P3 | allocator 优化 | 比较尺寸复用、分配顺序及保留策略，观察 allocated/reserved/设备占用 | 可降低碎片或保留量，不能替换已冻结的主指标 |
| 条件实验 | BF16 权重分阶段驻留 | 在同一 NPU 计算阶段间卸载/装载部分权重，测量传输与延迟 | 权重无需量化，但可能损失加速并增加中间传输 |
| 独立精度实验 | INT8 等量化 | 核对NPU算子支持、常驻字节、工作区、动作质量及完整闭环 | 改变精度条件；不能直接归入当前同精度异构优化收益 |

### 需要避免的错误预估

- 源码中存在按 `max_position_embeddings` 分配 KV 的函数，不代表当前有效路径实际分配了该容量。须以真实调用和张量字节为准。
- drafter 共享 embedding 已在当前推荐实现中使用，不能再次把同一项记成新增节省。
- 部分融合和 action head 候选此前出现整模型动作差异，未进入当前通过配置，不能计入无损优化收益。
- 不能通过关闭补偿、减少候选、改变 batch 或缩短任务来制造显存差额。

## 六、权重卸载与100 MB/s目标的冲突

权重卸载必须同时评估速度和传输，不能只看NPU占用降低。

例如，**假设**每个策略动作都重新搬入2 GB权重，即使只有1动作/秒，单向传输也约2 GB/s，已明显高于暂定100 MB/s口径。该例只说明约束关系，不是本轮实测。

本轮修复后的8步诊断，B1/B2观察到的 H2D逻辑字节分别为4,826,336/9,705,148，D2H为37,296/20,096。它们含输入且未完整覆盖后端DMA，不能用于判定100 MB/s通过，也不能与另一轮trace的SDMA时长拼接求有效带宽。

因此，权重卸载应作为单独候选，先量化“省多少、慢多少、搬多少”，再决定是否符合项目的联合目标。

证据：[传输与资源限制](../../../outputs/acceptance/ascend_20261019T0730Z/reports/T12_resource_limitations.md)。

## 七、下一轮最小实验

1. 完成 B0 的NPU适配与参考差异核对，先冒烟和完整单回合，再采正式资源对照。
2. 独立诊断轮建立显存账本，记录唯一 storage 与实际 dtype；详细分析器不用于低干扰速度测量。
3. 先测“仅减少结果驻留”和“仅调整KV/工作区”两个候选，再测合并配置，避免重复计算收益。
4. 每个候选先通过逐动作/token精确一致门限，再验证完整配对闭环；保持BF16、全部路径、算法参数、输入预处理一致。
5. 在独立进程中记录加载后常驻量、含初始化全程峰值、完整预热后的稳态峰值；同时保存原始bytes、GB/GiB、CPU RSS和厂商采样。
6. 低干扰回放至少三轮并交替顺序；尽量与同机重型诊断错开，报告均值、中位数、nearest-rank P95及轮间波动。

候选表至少包含：`run_id、基线身份、源码/权重哈希、精度、动作门限、任务结果、allocated峰值、reserved峰值、设备/进程占用、H2D/D2H覆盖、推理/闭环时间、限制`。

本轮尚未证明节省2 GB。后续以已确认的B0、单位和统计边界判定，保留未达标结果；若仍需改变权重驻留或精度条件，再单独登记方案与对照。
