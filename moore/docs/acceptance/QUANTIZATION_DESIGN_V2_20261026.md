# KERV / MUSA 低精度损失量化机制设计 V2

日期：2026-10-26。状态：**机制设计与真实权重静态预算已完成；新量化算法、模型精度与部署性能尚未实测。** 本文中的阈值和配置是研发方案，不是甲方已确认的验收标准。本轮不改默认推理配置，不改写已封存的测试campaign。

## 1. 建议采用的机制

采用 **激活感知校准 + GPTQ误差补偿 + 投影内部BF16保护组 + 累积误差约束**。以W8A16为主：权重多数INT8，激活和GEMM仍BF16；敏感投影及少量敏感权重组保留原BF16。第一版不量化激活、KV、动作头、视觉及drafter，也不引入INT4。

当前推荐起始候选是：verifier中间26层的78个MLP投影采用group32 INT8；前2层、后4层及所有attention投影保持BF16；量化投影内最多约5%的连续输入列组另存原BF16值。层号只是保守起点，最终由分层误差和独立验证决定，不能预设所有down_proj都不敏感。

真实checkpoint字节预算：这个起始候选的MLP权重静态节省约 **2.696GB**，已计INT8主存储、FP32分组scale、FP32通道逆scale、BF16保护组及int32索引，未扣除保护组对应的冗余INT8存储。它是显存收益的可行性预算，**不是已实测GPU峰值，更不表示精度已经保住**。

若这一预算下无法通过精度门槛，应增加BF16保护并报告显存减少；不能为了凑2GB而强制接受有问题的量化配置。

## 2. 为什么之前的混合量化没有解决问题

之前实现是分组对称最近舍入（RTN）：每组取absmax/127，直接round为INT8，再选择哪些完整MLP投影量化。其局限包括：

1. 没有按真实输入激活重建投影输出，也没有补偿舍入误差。
2. 保护粒度为整个投影，无法在一个投影内只保留敏感通道附近的少量权重。
3. 校准只来自task0的一条141帧历史轨迹，第一轮8帧、第二轮16帧；第二轮还利用了已观察过的误差，不能作为独立测试。
4. 校准检查动作token，却没有量化动作logit margin、KERV接受阈值变化和多层累积误差。单帧相同也不代表下一帧闭环状态相同。

已有事实是：group128混合策略57个INT8投影，完整回放105/141动作相同；group32混合策略仅3个INT8投影，仍只有122/141。两者task0/state0均失败，不能把“提高位宽/缩小group后一定保精度”当成结论。

另一个独立问题是运行时漂移：192个权重投影逐bit无损还原后，optimized运行时仍只有139/141固定动作相同且闭环失败；native运行时的170条动作则完全一致并成功。新机制必须区分权重量化误差与运行时数值变化，不能将所有分歧都归因于INT8，也不能宣称当前已定位到某个具体算子。

原始证据见[混合量化实测报告](MOORE_MIXED_QUANTIZATION_REPORT_20261026.md)。以下设计是在这些事实基础上的改进假设，不是对旧实验的重新解释或覆盖。

## 3. 精度分配

| 部位 | 起始精度 | 理由及后续规则 |
| --- | --- | --- |
| 视觉编码器、视觉到语言投影 | 原BF16 | 保持视觉输入链路稳定；当前不拿视觉部分换显存 |
| token embedding、lm_head/动作头、norm | 原BF16 | 保护输入及输出边界；上游隐藏状态有误差时，BF16动作头仍可能产生不同动作，因此仍需检查输出 |
| drafter / ea_layer | 原BF16 | 第一阶段只改变verifier，避免两端同时变化使接受机制难以归因 |
| attention的q/k/v/o | 原BF16 | 初版不改变注意力和KV来源；不是声称attention已被证明最敏感 |
| verifier第0–1、28–31层MLP | 原BF16 | 边界层保护的初始假设，后续可由实测缩小或扩大 |
| verifier第2–27层MLP | W8A16，优先group32 | 用真实激活选择scale并补偿误差；group64为显存/性能对照 |
| 投影内高敏感输入列组 | 原BF16覆盖 | 每个组覆盖连续32列，所有输出行共享组位置；候选保护比例0%、2%、5% |
| 激活、KV cache、动作归一化及夹爪后处理 | 原配置 | 不叠加激活或KV量化；保持动作协议及Kalman/阈值参数一致 |

“保留BF16”意味着从只读checkpoint保留原值，而不是把先前反量化的近似值再次转成BF16。

## 4. 用真实激活重建，而不是只看权重absmax

对一层Linear，定义输入 `X∈R^(N×d)`，权重 `W∈R^(o×d)`，希望近似输出 `Y=XWᵀ`。优化目标为：

```text
min || D^(1/2) X (W - W_hat)^T ||_F²
H = X^T D X / sum(diag(D)) + λ I
```

D是非负样本权重，首版采用明确定义的阶段/位置权重，不声称已经实现梯度Fisher。使视觉/文本prompt、teacher-forced动作位置和实际验证树候选均有覆盖；不能让数量更多的视觉token完全淹没7维动作决策。

借鉴GPTQ的近似二阶补偿，量化当前列后，将其重建误差分配给后续可量化列，降低真实输入分布下的输出误差。[GPTQ原论文](https://arxiv.org/abs/2210.17323)支持这类机制；论文的语言模型精度与GPU加速结果不能直接当成本VLA/MUSA的结果。

具体约束：

- 初始damping取 `0.01×mean(diag(H))`；H条件数/Cholesky检查不通过时记录原因，再按冻结规则增加damping。不能忽略NaN或直接把失败标为成功。
- 极少激活的列不等于永久不重要。不采用“校准中H对角为0就把原权重置0”的快捷方式；需扩充覆盖或将所属组保留BF16。
- 投影/Transformer block顺序量化。后续block使用当前候选实际产生的输入统计，同时保留BF16教师目标，避免只在全BF16上游输入下重建，忽略累积偏移。
- 每次只处理一个投影或一个block，限制激活reservoir和FP32 Hessian内存；量化产物完成后释放校准备份。校准双驻留显存不能写成部署显存。

AWQ提供了根据激活识别重要通道、采用等价缩放保护它们的依据，见[AWQ原论文](https://arxiv.org/abs/2306.00978)。本设计不是直接调用已适配MUSA的AWQ/GPTQ包，也不能未经验证声称两种算法叠加必然更好；需要保留GPTQ-only、AWQ-only及组合消融。

### 4.1 如组合AWQ与GPTQ，缩放空间必须一致

定义正对角矩阵S：

```text
W_s = W S
X_s = X S^(-1)
X_s W_s^T = X W^T
H_s = X_s^T D X_s / sum(diag(D)) + λ I
W_hat = BF16( FP32(Q_s) S^(-1) )
```

S根据校准激活统计，在预先登记的有限网格中搜索；例如指数α取0/.25/.5/.75/1，归一化后限制scale动态范围，具体搜索形式作为本地设计写入manifest。GPTQ必须使用缩放后的X_s/H_s，不能对W_s继续套用原H。

MUSA运行时直接解码得到W_hat，再以原始BF16输入X做GEMM；不额外将输入先除S并舍入一次。这个实现选择减少额外的激活舍入，但不保证与另一种算子顺序逐bit相同，必须用部署算子的实际结果重新验证。

## 5. 在一个投影内部保护敏感权重

每个输入方向分成连续32列的组G。根据校准激活和当前量化误差，评估组的输出损失：

```text
E_G = W_G - W_hat_G
risk(G) = trace(E_G H_GG E_G^T)
```

先用对角近似预筛，再用采样输出重建评估高风险组。按风险排序保护少量组，而不是仅挑最大的权重。候选比例0%、2%、5%分别验证；按组向上取整，实际比例可能略高，预算也按实际组数计算。

保护组保存原BF16列块。GPU解码INT8后将这些位置覆盖回原BF16，再执行一次原生BF16 GEMM。这样不用把“量化输出”和“残差输出”经过两次BF16 GEMM相加，减少额外舍入和调用，但解码/覆盖仍有开销。

保护组必须在GPTQ补偿之前冻结。将受保护列记为P、其余为U，保护列误差严格为0；对U使用H_UU重建，补偿更新不能再改写P。若先做GPTQ、最后才把部分权重恢复原BF16，原有补偿目标会改变，应重新校准，不能直接假定改善。

若局部保护仍不能控制一个投影/整个block的输出误差，整投影/整block恢复BF16。保护比例如超出预算，记录“当前显存目标下精度不可达”，不放宽质量规则凑目标。

## 7. 同时约束输出误差和决策翻转

仅降低权重MSE或隐藏状态MSE不够。至少记录：

1. 投影及block输出：相对RMSE、P99误差、最坏帧，分prompt/动作/树候选统计。
2. teacher forcing动作logits：KL、最大logit差、允许动作词表内top1/top2 margin、排序翻转率。
3. 动作：6个连续维度的token/bin差与归一化动作误差，夹爪切换误差单独计数，不能被全局均值稀释。
4. KERV控制：草稿接受长度、拒绝位置、动态阈值跨越、直接补全/Kalman触发率及其连锁变化。
5. 闭环：任务成功、动作数、超时、异常、动作时间连续性；相同帧回放不替代实际执行动作后的状态反馈。

若BF16某个位置top1/top2间隔为m，实际测得全允许词表logit最大偏差为ε，`2ε < m`足以保证**该次同输入位置**的top1不变。这可以解释哪些决策更脆弱，不能对未见输入给出全局保证，也不能替代KERV接受规则的验证。

建议在V上采用以下保守研发筛选值，执行前再以动作解码实际bin数冻结：夹爪额外翻转为0；连续维度平均bin误差≤0.25、P99≤2、最大≤4；清晰margin位置的额外top1翻转接近0。它们是淘汰明显问题候选的启发式，不是“满足就保证SR”的定理，也不直接换算成毫米/弧度。

多层累计方案必须重新整体回放；不能因为每个投影独立达标，就认为一起量化也达标。BF16重复推理本身不稳定的帧单独标记、分析，但不从最终指标中删除，也不能据此自动放宽量化门槛。

## 8. 有限候选及实验顺序

先只用native KERV运行时，同一运行时比较BF16、RTN和新量化机制。这样不同时改变融合/缓存及权重，便于排查。建议冻结8个配置：BF16参考、RTN32参考、GPTQ32、GPTQ64、AWQ32、AWQ+GPTQ32（保护0%、2%、5%）。边界层及其他BF16部位先固定。

执行顺序：

1. BF16重复基准、teacher forcing动作协议、层输入采集和样本划分自检。
2. 真实投影的scale/补偿/保护组计算与CPU解码核对；小型Transformer及KV续推检查。
3. 选一个block实测，确认误差目标确有改善；没有改善不直接扩展全模型。
4. 顺序量化全选中block，加入逐block输出约束；超限恢复BF16并更新实际字节账。
5. 在V上同输入回放3轮，再做少量完整配对闭环。失败时只能用C/V继续调参，失败记录保留。
6. 固定最终policy、源码/权重/校准哈希及完整精度清单，在T上运行300对完整回合；不把回放帧数当任务样本数。
7. 精度稳定后再单独接回optimized运行时，保留相同开关的BF16控制；逐项启用并检查。BF16 attention的QKV融合可单独评估，不能与量化MLP强行堆叠，也不把融合打包减少的reserved全算成量化收益。

这是单机可串行执行的方案。C/V/T与多候选闭环会占用数小时到更长；本轮只完成设计与静态预算，未将这些计划写成已完成实验。

## 9. 精度目标与验收方式

研发目标：逐平台配对成功率下降尽量控制在1个百分点以内，同时报告相对下降；任务书的“损失小于5%”仍要同时保留百分点与相对值，不能擅自用更宽松口径替换。形式验收及其他模型/平台/芯片矩阵仍按TestOutline执行。

定义：

```text
ΔSR_pp = 100 × (SR_quant - SR_BF16)
relative_drop = (SR_BF16 - SR_quant) / SR_BF16  # 基线为0时不定义
regression_pair = BF16成功、量化失败
recovery_pair = BF16失败、量化成功
```

成功率之外列出每task、每状态、regression/recovery配对数，不能用其他任务的改善掩盖一个关键任务退化。基线本身失败的回合仍进入分母，不能只保留BF16成功集后称作整套SR。

30或100回合pilot不能证明“小于1个百分点”。即使100个统计独立配对没有出现一次regression，零事件的一侧95%上界仍约2.95%；要把这种事件概率上界压到1%以内约需299个独立样本。该计算针对regression事件概率，不等同于完整配对SR差的置信区间。实际回合有任务聚类及状态相关性，需要报告配对差区间和任务分层/聚类敏感性；增加相同初态的重复seed不自动增加有效独立样本数。

部署性能单独报告：单模型冷启动allocated/reserved峰值、整卡采样、CPU内存、加载时间、首步及稳定段模型/pipeline耗时、完整任务耗时、接受长度。先以实际精度结果选择候选，再判断2GB和时延目标能否同时达到；不承诺MUSA原生INT8 GEMM加速。

## 10. MUSA与FlagScale实施约束

- 数学量化算法与部署kernel解耦；GPTQ校准可用CPU或已验证的MUSA线性代数操作，不为使用CUDA-only包而升级本机驱动/环境。
- CPU从只读checkpoint转换并导出量化buffer/scale/保护组，再上卡。部署不保留完整BF16模型备份，否则静态字节账失去意义。
- 解码kernel融合group反量化与通道逆缩放，覆盖BF16保护组后调用原生BF16 GEMM。MUSA位序、尾组、非连续输入、mask和稀疏位置都需检查；不使用未经验证的多GEMM误差补偿路径。
- 冻结policy必须携带模块shape、实际精度/group、scale、保护位置、校准输入来源、base/drafter哈希及运行时开关；拓扑/shape/哈希不匹配严格退出，不能把静默BF16回退写成量化成功。
- 复用FlagScale入口但单独定义新profile/manifest，明确这是本地新增校准量化后端，不声称上游已接收。
- 关键buffer在设备上的dtype、实际字节数和真实forward次数纳入证据。临时解码权重计入峰值，校准期间的BF16双驻留不参与部署比较。

预算读取当前真实safetensors header，确认96个MLP投影、18个原BF16投影、78个混合投影。每组保护采用ceil规则，包含保护权重冗余主INT8存储、所有FP32元数据和int32组索引，不是理想化8bit比例。

| 32 | 5% | 2.696183 |
| 64 | 0% | 3.295119 |
| 64 | 2% | 3.094054 |

同一解码临时投影最大约90.18MB，allocator、激活/工作区及尚未实现的kernel额外开销另计。上述数字只证明预算有实现空间，不推断量化后的任务精度或峰值节省。
