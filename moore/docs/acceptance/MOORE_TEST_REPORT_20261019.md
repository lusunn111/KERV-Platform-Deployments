## 1. 结论与适用范围

本机已经完成真实权重推理、LIBERO 闭环、FlagScale 启动、KERV 原生/优化对照，以及独立上游 SpecVLA 的 MUSA 兼容移植和闭环验证。现有算子及运行时优化确有速度收益，但新一轮测试发现动作一致性缺口，尚不能作为“多轮无损优化全部通过”的交付结论。

- 三对 KERV 闭环中，仅 seed 7 的 170 个动作、动作 token、执行动作和输入观测哈希全部一致。该对照排除首步后的模型均值加速 **2.3103×**，包含首步的 pipeline 均值加速 **2.0359×**，闭环墙钟加速 **1.6786×**。
- seed 17、27 分别在第 **78、107** 个动作首次出现 token 差异；这两个时刻的输入观测哈希仍相同。seed 17 的 native 到 220 步未完成任务，optimized 在 170 步成功。两对一致性判定 **FAIL**。
- 固定输入三轮回放中，B1/B2观测哈希423/423相同，动作/token为**422/423相同**，动作保持门禁同样**FAIL**。模型/pipeline均值比为2.2751×/2.1988×，只能作为存在输出差异时的描述性统计。
- 真实 SpecVLA B0 在 162 步完成同一初始任务。与 B2 的整回合 pipeline 时间之和相比，耗时比为 **1.2294×**；由于动作数不同、算法不同、执行 harness 的日志开销也不同，该数值不能替代同轨迹系统优化结果或任务书 A100 指标。
- B2 相对真实 B0 的平均接受长度差为负；allocated 和 reserved 峰值均更高。本轮没有达到“平均接受长度提升 >0.5”和“显存节省至少 2GB”。
- A100 参考、智源 VLA、另外两个认可平台、其他国产芯片、独立第三方及签认材料未在本机完成。正式验收不作通过判断。

固定输入三轮回放属于另一项实验，结果见第 7 节。它固定每帧观测与历史，评估回放一致性和预热后时延；闭环则让前一动作影响下一观测，两者结论分别保留。

## 3. 对照组及实际实现

| 组 | 身份 | 算法及执行方式 |
| --- | --- | --- |
| B0 / specvla | 真实上游 SpecVLA 的独立 MUSA 移植 | 固定接受阈值 9；原始草稿/验证逻辑；不接入 KERV Kalman、动态阈值及投影融合；隔离 harness |
| B1 / native | 现有 KERV 原生路径 | 保留 KERV 历史动作估计、Kalman 分支、周期补全及动态阈值；由 FlagScale 桥接启动 |
| B2 / optimized | KERV 算子及运行时优化组合 | 在 B1 算法基础上启用投影/局部算子融合、RoPE 融合、CPU C++ 树、KV/工作区/控制缓冲复用及输入缓存等；由 FlagScale 启动 |

本轮不是把 `KERV native` 命名成 SpecVLA。B0 来自 `ports/specvla_musa/`，其 `cnets.py`、HF `utils.py` 和 `modeling_prismatic.py` 与冻结上游原件哈希一致；MUSA 设备选择、CPU checkpoint 加载、共享冗余 embedding、离线 processor、同步计时及采集改动另有 manifest 和补丁。B0 接受边界及小模型 CPU/MUSA 对照通过，最大误差约 1e-7 量级，判据为 1e-3，详见 `reports/B0_fixed_input_validation.json`。

KERV 动态阈值沿规划步数从 15 向 3 变化，规划时域 220。Kalman 主要使用历史模型动作/token；当前 OpenVLA 的 proprio 状态没有作为模型输入，实测关节/末端状态也没有直接进入该滤波链。现有 KERV 还保留每 4 个动作一次的直接 Kalman 补全路径，不能将全部补偿描述为“拒绝后才触发”。这些规则并非本轮为获得指标新增。

模型、drafter、verifier 和设备张量操作在 MUSA；仿真、processor、历史估计和树拓扑控制包含 CPU 执行。C++ 树构建属于 CPU 算子，不能描述成 GPU 树内核。任务书对补偿位于 CPU/GPU 的文字存在冲突，D08 未签认；具体分工见 [placement.md](placement.md)。

本机已经核实 FlagScale 桥接进入真实 KERV 执行入口。尚不能由此推断所有核心代码已被公开上游接收，或当前执行的是 vLLM 引擎。部署操作、算子原理和原有优化开关见[工作区 README](../../README.md)；其 2026-09-30 数字属于历史单回合结果。

## 4. 测试设计、计时和判定

主闭环固定 `libero_goal`、task 0、官方 state 0，任务为打开柜子中间抽屉；最多 220 个策略动作，初始稳定化 10 步另计。B1/B2 使用框架 seed 7、17、27，顺序 AB、BA、AB。`get_libero_env` 内部仍固定 `env.seed(0)`，所以这是同一初始状态的重复，不是三个独立环境状态，也不是完整 LIBERO 成功率评估。

原始清单与追加清单分别冻结：`inventory/cases.csv`、`cases_addendum_01.csv`（采集失败后的唯一重试）、`cases_addendum_02.csv`（真实 B0）、`cases_addendum_03.csv`（原始观测采集）。每次新建 run ID；不向已有结果追加、不删除失败、不用重试覆盖原记录。8 步冒烟、8 步传输诊断、额外观测采集都不进入主闭环 SR 分母。

共登记13个run：12个执行/采集完成，1个早期采集汇总失败并保留；其中完整闭环7个，任务成功6个、失败1个。固定输入回放另按独立协议登记，未混入这13个run的主矩阵分母。

| 指标 | 边界/判据 |
| --- | --- |
| `model_seconds` | predict_action 调用到 MUSA 同步完成；不含此前 CPU processor；普通闭环含其原有运行统计开销 |
| `pipeline_seconds` | 原始观测哈希后，图像处理、processor、传输、模型及控制、动作转换，直到 env.step 前 |
| 首步/稳态 | 首步原样保留；另报排除首步均值、median、nearest-rank P95；不只展示较快口径 |
| 闭环墙钟 | 已稳定的首观测到终止 env.step 和逐步采集完成；包含仿真及步间日志；不含加载、稳定化、录像编码 |
| launcher 时间 | 宿主机启动到子进程退出；含加载、录像等，与闭环/模型耗时分开 |
| B1/B2 一致性 | 逐步 token、raw action、executed action、输入观测哈希以及长度/任务结果核对；最终动作有差异则门禁失败 |
| 接受长度 | 每次真实验证一个样本，全拒绝计 0；候选 posterior 前缀与动作边界内实际提交前缀分别报告 |
| 显存 | allocator allocated/reserved 的冷启动、首步后窗口分别采集；全运行峰值取最大；设备 CLI 采样单列 |
| 正式指标 | 严格 `>0.5`、`<5%`、`<100M/s` 等不放宽；D01–D08 未确认，不擅自选择有利定义 |

观测哈希包含 incoming RGB、末端位置、末端四元数、夹爪状态及各字段 shape/dtype。相同哈希能证明采集输入相同，不表示这些字段全部用于模型和 Kalman。

## 6. 动作分歧证据及原因边界

seed 17 的第 78 个动作（JSON 0 起始索引 77）：

```text
native:    [31876, 31908, 31933, 31899, 31902, 31931, 31744]
optimized: [31876, 31908, 31933, 31899, 31902, 31894, 31744]
```

该步之前的最终动作和用于 Kalman 的历史前缀一致，该步观测哈希相同。但内部候选路径/接受序列可能更早变化，不能将最终动作首次差异等同于内部计算首次差异。

另一个新进程 `capture_optimized_s17` 在 141 步成功，而主测试 `full_optimized_s17` 为 170 步成功。两者第 105 个动作（索引 104）首次 token 不同，当步输入哈希仍相同。额外采集不是主矩阵的替代重跑，也没有进入主 SR 分母。native 的不同框架 seed 之间同样观察到分歧。

上述事实说明需要继续排查跨进程/seed 与数值路径敏感性。本轮不能据此单独认定是 C++ 树、融合投影、缓存、未初始化权重或 MUSA 内核中的某一个问题，也不能把现象一概解释为“环境不同”。已存在相同观测下的模型输出差异。报告阶段没有通过修改算法、阈值或容差来掩盖分歧。

固定回放已保存实际加载参数哈希：native 与真实 B0 的 992 个同名参数全部一致；native/optimized 共有的 827 个同名参数全部一致。优化路径移除了 165 个独立投影参数名，由融合/缓存表示承接，当前哈希没有完整覆盖这些 packed buffer，因此该检查不能证明融合缓存逐字节相同。检查结果为 `reports/replay_parameter_comparison.json`。
