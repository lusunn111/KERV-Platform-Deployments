### 4.1 三组基线与加速公式

B0 = Spec-VLA，使用可追溯实现、模型和其正式算法参数。

B1 = KERV原生，含运动反馈/运动学补偿和动态接受机制，关闭待评估的额外运行时优化。

B2 = KERV优化，算法、权重、输入和动作协议与B1相同，启用本次通过正确性验证的异构/运行时优化。若要单独归因异构部署，再增加B1-H：只改变CPU/加速器分工，其他优化保持不变。

同一计时指标、同一任务集合和同一统计窗口下：

```text
算法加速比 = T(B0) / T(B1)
运行时加速比 = T(B1) / T(B2)
总加速比 = T(B0) / T(B2)
耗时降低比例 = 1 - T(B2) / T(B0)
```

只有数据条件完全一致时，总加速比才等于前两个比值的乘积。最终对任务书的基线是B0。若B1比B0快，总比值可能更大；若B1更慢也可能更小，均以实测为准。禁止拼接不同日期、芯片、任务、动作协议或计时边界的旧比值。

B0必须在目标后端真实运行并与其参考实现核对。不能仅关闭KERV的Kalman/阈值后就宣称完全等价于Spec-VLA；须检查草稿树、验证策略、缓存、动作分块、阈值和停止边界，形成差异表及固定输入对照。

### 4.2 时间、成功率、接受长度和资源公式

至少记录四层时间：模型加载/冷启动时间；同步边界内的单次纯模型推理时间；包含processor、输入搬运、模型、反馈及动作解码的策略链路时间；从首个观测就绪到回合终止的闭环墙钟时间。仿真`env.step`、日志和视频耗时另列。正式65 s/task使用D02确认的那一层；同时保存其余层，避免以后无法对齐。

后端异步执行在必要边界同步。正式计时不启用重型性能分析器；性能轨迹另跑相同配置的诊断轮，记录关联ID。首动作和编译/预热耗时单列；不得静默丢首步或只保留快的样本。若端到端包含仿真，不得用排除仿真的数值替代。

```text
SR = 成功回合数 / 预登记有效评测回合总数
百分点损失 = 100 × (SR_B0 - SR_B2)
相对损失 = (SR_B0 - SR_B2) / SR_B0      # SR_B0=0时记未定义
平均接受长度 L = sum(每次验证实际接受的候选前缀长度) / 验证调用总数
接受长度改善 = L_B2 - L_B0             # 要求 >0.5，非50%
双向中间传输B/s = (H2D_bytes + D2H_bytes) / 已冻结的观察窗口秒数
拷贝期有效速率 = (H2D_bytes + D2H_bytes) / 实际拷贝累计秒数
显存节省bytes = 同口径基线峰值bytes - 测试峰值bytes
```

传输两种速率含义不同，不能挑较小的作为通过证据；高PCIe峰值规格也不能证明低数据开销。统计真实跨设备复制，不能把一次完整张量传输按视图大小少记，也不能把缓存声明当成减少了实际传输。模型初次加载可单列，但输入、控制结果、反馈及每步隐式`.cpu()`/`.item()`等搬运不能漏记；GPU-GPU和CPU内存拷贝另列。

显存至少同时记录框架`allocated`（已分配）峰值、`reserved`（保留）峰值、厂商工具的进程/设备占用及采样间隔；不支持的接口明确标缺失。其他用户进程占卡时设备总用量不能直接归本实验。加载后基值、含初始化的全运行峰值与预热后稳态峰值分别保留，不能只记`reset_peak`后的增量来声称总显存节省。

## 5. 固定测试集合和运行规则

下列是本计划的建议实施规则，任务书没有规定这些样本数量。执行人员可根据资源及平台官方协议调整，但必须在看结果前锁定并记录，不能测后缩小集合。

冒烟：每个可用模型/平台先做1个任务×1个初始状态×8个策略动作，只检查运行、字段和动作有效性，不算完整任务成功率。

完整回归：至少1个配对完整回合，达到平台规定最大步数或明确成功/失败终止；B1/B2核对每步动作、token、维度、数值及成功状态。8步停止不能当成任务失败，也不能当成任务成功。

正式评测：每个平台选定全部预登记任务；每任务固定10个官方初始状态，分别用seed 7、17、27执行，B0/B1/B2保持相同清单。若任务或状态不足10个，使用可用集合并记录，不复制同一状态凑样本。若该平台已有认可的标准协议，采用该协议并保留差异说明。例：10任务×10状态×3种子=每组300回合，三组900回合；先估算时长与磁盘，再排期。

固定观测回放：每种配置完整预热序列1遍，再测至少3遍，按AB/BA交替顺序分轮运行，记录全部原始时延。该结果用于同输入的系统收益归因，不能代替闭环成功率。旧昇腾脚本默认测2遍，正式3遍须显式设置并核对实际记录。

每个模型、平台、芯片分别报告均值、中位数、P95、样本数、成功/失败数；给出不确定性区间作为补充，区间不改变任务书阈值。P95统一采用nearest-rank（排序后第ceil(0.95N)项），同时保存排序前原始数组。跨平台仅可提供额外汇总。

失败处理：策略导致的失败、超步数和超时保留在原分母中；环境未能初始化、设备故障等基础设施异常单列并保留原始回合ID和重试链接。每个基础设施异常最多自动重试1次；再次失败标BLOCKED/FAIL。不能删掉失败后不断重跑直到成功。运行中断不产生PASS，续跑只能补缺失任务ID，不向旧JSONL追加重复回合。

现有启动器默认`KERV_ACTION_PROTOCOL=seven`，B1/B2保持一致；历史摩尔协议与seven不同，不能跨协议拼接性能或轨迹。`--max-episode-steps`也会设置规划时域，不能为8步冒烟直接改它而不恢复规划长度；若冒烟要8步，显式用经核对的override保持规划220，并确认解析配置。

同输入回放的现有入口如下，仅在历史观测文件完整、配置和输入哈希已锁定时运行；输出路径是容器绝对路径：

```bash
scripts/benchmark_kerv_moore_ascend.sh --samples 157 --repeats 3 \
  --output "/data/data/KERV/outputs/acceptance/${KERV_TEST_RUN}_replay"
```

该脚本比较KERV native/runtime，不含真正Spec-VLA，且固定读取历史观测路径。正式矩阵需要P02补参数化输入和B0，不能因为该脚本生成`benchmark.json`就标1.1通过。

另有`third_party/FlagScale/examples/kerv/`的原生集成入口，由`scripts/run_kerv_flagscale_ascend.sh`调用。它可能加载根目录旧实现，须核对`flagscale.models.kerv.entrypoint`、`KERV_SOURCE_ROOT`及所导入模块。P07应把最终选定实现接到统一FlagScale路径并做一致性验证，不能将旧原生入口的成绩当作新版移植版集成证明。

最后将运行副本的新证据复制回工程根目录对应新目录，核对文件数量与逐文件哈希。禁止覆盖旧`outputs/`和归档`imports/`。

### 10.3 两款芯片分别通过的最低适配检查
